## How status is read

Status is derived from what this document records; nothing here is a
maintained header.

- A **question** (`PA-Qn`) is open exactly when it has no `Ruling` field.
  `Authority` is `operator`, `self-under-standing-go`, or `defaulted`. A
  defaulted question is a conventional choice the map made and recorded; it
  is open to the operator but blocks nothing.
- A **cut** is landed when its `Landed` field names commits, and closed when
  every promise (`P<cut>.<n>`) in its Verdicts table has a verdict
  (`HOLDS | FALSIFIED | UNPROVEN`). The root agent fills `Landed` and the
  Verdicts; Hands and Soul do not edit this file.
- A **mutation** (`M<cut>.<n>`) names file, line, before and after; the commit
  it ran against is filled at execution. Mutations run against committed code
  and are restored with a reverse edit, never `git checkout`.
- A **finding** (`PA.f<n>`) is something no cut owns; each carries
  introduced-or-pre-existing, severity, and triage (`fix | operator | recorded`).
- The **ledger** carries an estimate per cut; the Actual column is computed
  from the diff at landing and is empty until then.

The pass is open until every cut is closed and every question has a ruling.

Every build and test named here runs on the Windows workstation and proves
Windows only. The Linux release is Idunn's build on Yggdrasil
(`gamecult-ops/runbooks/ghostlight-dungeon-yggdrasil.md`); the Dungeon bin lists
four more tests there (`#[cfg(target_os = "linux")]`, see the stock-lenses map).

## What the probes established

- **Probe B, the public boundary (compile, external crate).** A scratch crate
  outside the workspace (session scratchpad `probe-boundary`, path dependency on
  `crates/ghostlight`, `cargo check --offline`, scratch target removed; repo
  untouched) tried, from outside the library:
  - build an `InferenceRequest`: **E0451**, fields `purpose` and `provider` are
    private (`controllers.rs:115-118`); there is no public constructor
    (`tool_request` is `pub(super)`, `controllers.rs:6061`);
  - read `InferenceOutput.events`: **E0616** (`controllers.rs:148-151`,
    `pub(super)`);
  - read `PreparedInference.invocation`: **E0616** (`controllers.rs:132-135`).
    So a port "a consumer implements outside this crate" (the doc comment at
    `controllers.rs:376-380`) cannot read the request it must lower;
  - read `SubjectSnapshot.position`: **E0616** (`lib.rs:978`);
  - read `AffordanceSnapshot.entry.roles`: **E0616** (`patch.rs:889`).

  And these **compile** from outside: `ControllerPort::new(mailbox)
  .submit_controller(id, &opportunity, invocation)` (`mailbox.rs:688-731`);
  `WorldMailbox::submit_clock` (`mailbox.rs:356`);
  `serde_json::from_str::<WorldPatch>` and `::<DecisionInvocation>` (both
  derive `Deserialize` with `pub(crate)` fields).

  Consequence: Dungeon today can exercise for a Persona and submit a patch it
  deserialized, but it cannot run an inference, read an inference's output,
  read where anyone stands, or read what an affordance's roles are. Every
  surface the play agent reads or writes is library-private. This is PA-Q12.
- **Catalog size (measured from the checked-in fixture).**
  `sidecar/claude-sdk/test/schemas.json` is regenerated from `patch_tools()`
  by `sdk_inference.rs:1874-1913`. The 39 patch tools total 54,810 characters
  (parameters plus descriptions parsed from `patch.rs:5600-6128`). Dropping
  `declare_affordance` (8,055 characters of parameters on its own), `record_gap`
  and `submit` leaves 36 tools and 46,428 characters, about 13,300 tokens at
  3.5 characters per token. The largest are `create_commitment` (6,373), the
  three pressure tools (about 2,950 each), `bind`/`release` (1,625). A 22-tool
  core (relocate, transfer, consume, admit, bind, release, communicate,
  witness, acquire_knowledge, forget, create/discharge_commitment,
  advance/reduce_pressure, open/close_route, the five light declarations,
  set_persona_material) is 31,609 characters, about 9,000 tokens. This core
  was measured before PA-Q15 replaced `admit` with `mint`; the ruled starting
  list is under PA-Q7. A granted
  `speak` tool is 160 characters. Script: scratchpad `catalog_size.py`.
- **Source-verified facts the design rests on** (read, not probed):
  - Rust drives every connector round: an inert port returns one round's calls
    and the lane's evaluator re-derives the conversation from `completed`
    (`evaluate_elaboration_loop`, `elaboration.rs:1127-1223`;
    `evaluate_operational_loop`, `controllers.rs:5829`). The SDK port instead
    runs the loop inside one sidecar query and asks a lent
    `ToolResultOracle` (`sdk_inference.rs:417-498`); it holds one `gate`
    mutex for a whole query (`:423`), and `ToolResultOracle::answer` is
    synchronous (`controllers.rs:251-260`).
  - Routing is a model-name prefix with two slots, connector and SDK
    (`sdk_inference.rs:715-773`); `open_inference` refuses at open any
    `ControllerModels` lane no slot claims (`controllers.rs:2336-2376`).
  - The SDK sidecar is a private MessagePack child-process pipe
    (`SidecarFrame`, `sdk_inference.rs:36-70`) that borrows
    `codex_connector::CodexInputItem`; the connector port is the only user of
    the connector's socket client (`controllers.rs:406-527`). The one shared
    seam is the in-process `InferencePort` trait. This confirms the target's
    corrected Q1 premise (`5ff1d54`).
  - The Projector's typed context carries no knowledge
    (`projector_context`, `controllers.rs:4144-4166`); its **visible stimulus**
    is the subject's whole `knowledge`, each row rendered `said | seen_doing |
    known` with the speaker's label, certainty and text
    (`visible_stimulus`/`projector_knowledge`/`perceived_from`,
    `controllers.rs:4604-4655`). Rows carry `minted_at` (`lib.rs:1044-1047`)
    but nothing marks what arrived since the subject last acted. The kernel
    records every exercise as a `DecisionEvent { revision, scope, .. }` in
    `WorldState.events` (`lib.rs:774-793`, `:873`, pushed at `:4881`);
    `last_opportunity_at` is fictional minutes, not a revision (`lib.rs:853`).
  - Projector then Persona runs as two checkpointed stages of the narrative
    lane (`run_narrative` `controllers.rs:2770-2840`, `run_projector` `:3530`,
    `run_persona` `:3604`), followed by the Interpreter. `select_one`
    (`:1261`) matches any mode the opportunity names, so the Projector can
    run for a `Human`-mode opportunity; only `run_narrative`'s lane gate
    (`:2776-2780`) restricts it.
  - An exercise commits only if `exact_opportunity` finds the scope's current
    digest (`lib.rs:4244-4270`) and the caller equals the assignment's
    `expected_caller` (`lib.rs:738-752`, checked at `:1613` and `:1631` and
    re-decided at `:4866` and `:4897`). A `NarrativePersona`'s expected caller is
    `Controller(controller_id)`, which `ControllerPort::submit_controller`
    mints from the kernel-issued opportunity (`mailbox.rs:316-332`); a forged
    `controller_id` fails `ControllerMismatch`. A human's expected caller is
    its `Principal`.
  - Retry identity is caller plus body (`lib.rs:1466-1476`); an
    `ExerciseDecision` body carries its opportunity (revision and digest), so a
    retry rebuilt from a later snapshot is `CommandIdConflict`, not
    `AlreadyApplied`. A retry must resubmit the persisted body.
  - `require_system_capability` (`lib.rs:1703-1720`) and its twin
    (`apply_effect`, `:4768-4780`) admit a system caller for exactly the
    listed pairs. `require_answer` (`:1740-1764`) refuses every unanswered
    Active patch that declares or carries evidence, from every caller,
    including the owner. `require_patch_author` (`:4284-4315`) returns
    unconfined only for the owner.
  - `verify_state_shape` demands `controller_assignments.len() ==
    subjects.len()` (`journal.rs:488-495`); opportunities are minted for every
    assignment whose `mode()` is `Some` (`lib.rs:4115-4156`).
  - No operation grants or revokes an affordance: grants are written only by a
    subject's declaration (`ComponentOp` variants `patch.rs:1014-1188`;
    catalog "Draft-only", `lib.rs:868`). The genesis human subject is declared
    with `kernel_speak_grant()` only, at the commons (`mailbox.rs:115-145`),
    and `speak` has one precondition, `CanBroadcast { Colocated }`
    (`patch.rs:2283-2297`). `Relocate` needs a route from the subject's
    current place and cannot place an unplaced subject (`patch.rs:3613-3660`).
  - `render_world_structure` (`elaboration.rs:2172-2280`) is an existing
    whole-world renderer with bracketed ids, used by the seed lane only.
  - `SourceSpan::locate` (`ghostlight-persona-projection/src/lib.rs:366-375`)
    is the existing verbatim-quote locator.
  - The seed lane's key hashes ancestry (`seed_command_id`,
    `elaboration.rs:1545-1551`). Seeding runs as `sweep(1)` inside the
    owner's request (`runtime.rs:1786-1826`), one session at a time.

## Questions

### PA-Q1 Where the local backend lives

- **Asked:** 2026-09-22 (target Q1, premise corrected at `5ff1d54`).
- **Context:** the only shared seam is `InferencePort`. Every lane's request is
  a `CodexProviderRequest` (instructions, input items, tools, tool choice,
  parallel calls, effort, output cap); lowering that to OpenAI chat completions
  is mechanical (instructions → system, `UserText` → user, `AssistantText` →
  assistant, `ToolCall` → assistant `tool_calls`, `ToolResult` → tool message;
  response text → `InferenceEvent::Text`, `tool_calls` →
  `InferenceEvent::ToolCall`, inert). Probe B: an external port cannot read
  `PreparedInference.invocation`, and routing is a private two-slot router.
  Ghostlight never holds a credential; a local llama-server on loopback needs
  none.
- **Options:**
  - A: **a third port in the library**, `crates/ghostlight/src/local_inference.rs`,
    beside `sdk_inference.rs`. Loopback-only endpoint (refused at open
    otherwise), no credential header, inert tool calls, receipt digest over a
    typed receipt (request id, model, response id, usage, finish reason). A
    third routing slot claimed by a model prefix. Adds `reqwest` to the
    library (already in the workspace lock for Dungeon). About 250 lines with
    tests.
  - B: **a port in Dungeon.** Needs a public accessor on `PreparedInference`
    and a public routing seam that takes a foreign port. Two changes to the
    library's inference boundary so the port can live outside it; the port
    itself is the same code.
  - C: **a CultNet connector daemon** (a new service speaking a new CultNet
    contract, like CodexConnector). No invariant it protects exists here: a
    local model server is already its own process, and no credential needs
    isolating. It buys third-party credentialed endpoints, which the map says
    are needed "before third parties use the deployment" — not for the gate.
- **Recommendation: A.** Smallest surface, one owner for routing, and the
  loopback-and-no-credential rule keeps "Ghostlight never holds a credential"
  true by construction. C remains the path for credentialed third-party
  endpoints and is recorded as PA.f1.
- **Depends on it:** Cut 2.
- **Ruling:** A, as recommended.
- **Authority:** operator.
- **Ruled:** 2026-09-22.

### PA-Q2 What a Persona perceived

- **Asked:** 2026-09-22 (target Q2).
- **Finding:** partly yes. The visible stimulus already carries every row the
  subject holds, with speaker and `said | seen_doing | known`
  (`controllers.rs:4616-4638`), which is what speech heard and acts seen are
  (`Told { by }`, `Seen { by }`). It carries all of it, in `minted_at` order,
  with nothing marking what arrived since the subject last acted, so a Persona
  cannot tell the player's line of this turn from one heard ten turns ago.
- **Smallest addition (default):** a derived, per-row marker. The snapshot
  derives `last_acted_at: Option<u64>` for each subject as the greatest
  `DecisionEvent.revision` whose scope is that subject (one pass over
  `state.events`, no new state, no schema change), and `projector_knowledge`
  adds `"new": minted_at > last_acted_at` to each row (a subject that never
  acted sees every minted row as new). Nothing about who hears what changes;
  the kernel's `knowledge` stays the sole perception owner.
- **Cost:** the Projector's stimulus bytes change for every lane that renders
  one, including the offline narrative lane. Stored `NarrativeCheckpoint::Projector`
  rows stay valid: their integrity check does not rebuild the stimulus
  (`controllers.rs:788-822`).
- **Depends on it:** Cut 6.
- **Ruling:** default as above.
- **Authority:** defaulted.

### PA-Q3 The callable Persona turn

- **Asked:** 2026-09-22 (target Q3).
- **Context:** the stages exist; what binds them to `ControllerRunner` is the
  checkpoint store, the Interpreter stage and the runner's five-model open.
- **Options:**
  - A: **an unpersisted lane.** `pub struct PersonaLane` in
    `controllers.rs`, built from a `ControllerPort`, an `Arc<dyn
    InferencePort>`, a projector model and a persona model. Two methods:
    `pub async fn turn(&self, command_id, &DecisionOpportunity) ->
    Result<PersonaTurn, ControllerError>` (Projector then Persona, the
    existing prompt builders, returns the existing receipt-bound
    `PersonaTurn`), and `pub async fn narrate(&self, command_id,
    &DecisionOpportunity) -> Result<String, ControllerError>` (Projector only,
    for the player; Q11). No work-store row. A restart mid-turn repeats the two
    inferences; nothing was committed, and the returned turn is persisted by
    its caller (Dungeon's turn record, Cut 8).
  - B: **persisted.** Reuse the `Projector` and `Persona` checkpoints and end
    at a new terminal stage (`Spoken { turn }`). Resumable, but it needs a new
    stage, its integrity arm, its progression rule, and a `controller_work`
    row bump, and it gives the turn two durable owners (the work store and
    Dungeon's turn record).
- **Recommendation: A.** The prose is what is worth keeping and its caller keeps
  it; in-flight inference on a local machine is the cheap thing to lose. One
  owner for turn state.
- **Depends on it:** Cut 6.
- **Ruling:** A, as recommended.
- **Authority:** operator.
- **Ruled:** 2026-09-22.

### PA-Q4 Exercising on an actor's behalf

- **Asked:** 2026-09-22 (target Q4).
- **Finding: no kernel change.** Probe B compiled
  `ControllerPort::submit_controller` from an external crate. A Persona's act
  commits as that Persona's own `ExerciseDecision`, under the caller the
  mailbox mints from the kernel-issued opportunity, and admission is unchanged:
  `exact_opportunity` (scope digest), `expected_caller`, `require_granted`,
  `action::exercise` (preconditions, ceilings, band draw). The player's act
  commits through `submit_principal` with the player's own
  `VerifiedPrincipalEvidence`, which Dungeon already holds for the request
  (`runtime.rs:1571-1585`); the evidence's own expiry bounds it
  (`mailbox.rs:227-233`). Sealed admission is not weakened because nothing new
  is admitted.
- **What the kernel cannot check, Dungeon checks (Cut 8):** that the actor was
  dispatched this turn (or is the player), and that speech and display are
  literal spans of that actor's prose (invariant 4). Tool identity carries the
  actor (`<handle>__<kind>`, the grouped lane's precedent,
  `controllers.rs:73-75`), never a model-written argument.
- **Retry rule (Cut 8):** the exact `CommandBody` is persisted before it is
  submitted, and a resumed call resubmits those bytes under the same command
  id, so the kernel answers `AlreadyApplied` (`lib.rs:1466-1476`).
- **Ruling:** finding; nothing to rule.
- **Authority:** self-under-standing-go.

### PA-Q5 The play authority's shape

- **Asked:** 2026-09-22 (target Q5).
- **Default design:** `SystemCapability::Play` (`lib.rs:467-484`), unit-shaped.
  Minted by exactly one public method on a narrowed port,
  `pub struct PlayPort { mailbox }` in `mailbox.rs` with `snapshot()`,
  `submit_patch(command_id, WorldPatch)` and `advance_time(command_id,
  TickMinutes)`, both stamped (`submit_stamped`, `mailbox.rs:267`). The clock
  precedent maps one-for-one: a system capability with no session evidence,
  minted by one method, admitted for listed bodies only. Admission:
  - `require_system_capability` and its `apply_effect` twin admit `(Play,
    AdmitPatch)` and `(Play, AdvanceTime)` and nothing else;
  - `require_patch_author` returns `Ok(None)` (unconfined) for `Play`;
  - `require_answer` admits `(Active, None)` with declarations for `Play` and
    for no other caller; `Play` is refused in Draft (`WrongPhase`);
  - `require_clock_caller` admits `Play`;
  - `Play`, and no other caller, may declare a `Ruled` fact and `Mint`
    quantity (PA-Q15, ruled; shape under PA-Q15 "Design"). `Play` carries no
    evidence receipts, so its `Admit` is refused by the existing gate like
    anyone's without a receipt; it uses `Mint` instead.
- **History (superseded by PA-Q15):** this default first refused any `Play`
  patch carrying evidence (`PlayCarriesEvidence`), so that `Play` could not
  mint quantity. The operator ruled the opposite.
- **"Only one thing holds it":** the capability is compile-time narrowed like
  every other port; exclusivity is Dungeon constructing one `PlayPort` in
  `AppState`, pinned by a negative grep (Cut 3, Cut 8).
- **Option not taken:** binding `PlayPort` to the owner's verified evidence,
  like `SeedPort`. It would end a long play session at the owner's session
  expiry and buys nothing the journal's `System(Play)` attribution does not.
- **Depends on it:** Cut 3.
- **Ruling:** default as above; the name is the operator's to change.
- **Authority:** defaulted.

### PA-Q6 Retirement's shape

- **Asked:** 2026-09-22 (target Q6).
- **Finding and default:** retirement is a subject state written by a
  component operation.
  - State: `ControllerAssignment::Retired` (`lib.rs:700-722`). `id()` and
    `mode()` return `None`, so `derive_opportunities` mints nothing for it
    (`lib.rs:4125`) with no new filter, and `controller_assignments` stays the
    sole answer to who may call (`lib.rs:836-838`). `expected_caller`
    becomes `Option<CallerId>` and returns `None` for `Retired`; both call sites
    compare `Some(caller)`. The shape check's `len ==` clause is unchanged.
  - Operation: `ComponentOp::Retire { subject: Ref<SubjectId> }` resolving to
    `ResolvedOp::Retire { subject }`. Applied: the assignment becomes
    `Retired`, the subject's `positions` entry and `affordance_grants` entry
    are removed. `subjects`, `events`, `knowledge`, holdings, facts and the
    journal keep everything, which is "stays in history".
  - Refusals: retiring an already retired subject is `NoOperationEffect`;
    retiring an `ExternallyControlled` mirror is refused (another world owns
    it); a confined author (elaborator, consumer) is refused by
    `confine_to_ground` (`OutsideJurisdiction`) whatever the subject's place.
    Owner and `Play` may retire.
  - What readers see: no opportunity, so no dispatch (Dungeon dispatches from
    opportunities) and no act (`exact_opportunity` → `OpportunityMismatch`); no
    position, so `audience` (`lib.rs:3053`) never reaches it and the
    Projector's `present` omits it; `SubjectSnapshot` gains `pub retired: bool`
    so the agent's view and the surface can say so. Preconditions read the
    actor's own state and are never reached for a retired actor.
  - Replay: `apply_effect` applies the resolved op like any other, so replay
    reproduces it.
  - A body that matters afterwards is the agent's `declare_resource` in the
    same patch, as the target says.
- **Schema:** `ControllerAssignment`, `ComponentOp`, `SystemCapability` all
  change shape, so `STATE_SCHEMA`/`COMMIT_SCHEMA` bump `consumer.v5 → v6`
  (`lib.rs:172-173`, pinned at `consumer.rs` as for L1), in one cut with Q5.
- **Not done (recorded, PA.f4):** a retired subject's commitments, pressures
  and dependency edges stay and the clock keeps deriving motion over them.
- **Depends on it:** Cut 4.
- **Ruling:** default as above.
- **Authority:** defaulted.

### PA-Q7 The agent's catalog, and whether a small model plausibly handles it

- **Asked:** 2026-09-22 (target Q7).
- **Measured:** above. The kernel side without `declare_affordance` is 36 tools,
  ~13,300 tokens; a 22-tool core ~9,000 tokens. Dungeon adds `dispatch`,
  `ask_player`, `end_turn` (small), plus one `<handle>__<kind>` tool per granted
  entry per actor in the scene (160–1,500 characters each). With Cut 4 and
  Cut 5, `retire` and `grant_affordance`/`revoke_affordance` join the kernel
  side.
- **Plausibility:** nobody has measured Bonsai 2 on this. A 13k-token stable
  tools prefix is reused from a llama.cpp slot's KV cache when the prefix is
  byte-identical, so its cost is paid once per slot; the risk is selection
  accuracy over ~40 tools, not tokens. Strict-schema grammar enforcement on
  llama-server tool calls is a property of the server build and must be
  checked on Raven's machine (PA.f2).
- **Options:** A: the whole kernel catalog minus `declare_affordance`. B: a
  curated Dungeon list of `PATCH_TOOLS` names (Dungeon policy, pinned ⊆
  `PATCH_TOOLS` by test, the lens `leads_with` precedent), starting from the
  22-tool core plus `retire` and `grant_affordance`.
- **Revised by PA-Q15 (the starting list Cut 8 pins):** `admit` leaves the
  list, because `Play` holds no receipts and every `Admit` it wrote would be
  refused; `mint` takes its place. `declare_fact` stays, and its `standing`
  now offers `ruled`. `witness` and `acquire_knowledge` (`Witnessed`) stay,
  because they are how a ruled fact reaches a subject and so the Projector.
  The list: `relocate, transfer, consume, mint, bind, release, communicate,
  witness, acquire_knowledge, forget, create_commitment,
  discharge_commitment, advance_pressure, reduce_pressure, open_route,
  close_route, declare_place, declare_route, declare_resource, declare_fact,
  declare_subject, set_persona_material, retire, grant_affordance,
  revoke_affordance` (25 tools). Its size is re-measured from the fixture
  after Cut 5.
- **Recommendation: B**, measured at the gate against A on the same turn
  script; the list is one constant and widening it is a one-line change.
- **Depends on it:** Cut 7 (the library takes a name list), Cut 8 (the list).
- **Ruling:** B, as recommended.
- **Authority:** operator.
- **Ruled:** 2026-09-22.

### PA-Q8 The turn lifecycle, and what survives a restart

- **Asked:** 2026-09-22 (target Q8).
- **Default design:** Dungeon owns one open turn at a time in its own CultCache
  store, `service/play-turn-v1.cc`, on the `app_session.rs` pattern
  (`OwnedRedbMessagePackBackingStore`, one row). The row, `PlayTurn`:
  `turn_id` (the `world.play` idempotency key), `opening_prompt` (built once
  from the snapshot and the player's text, then never rebuilt), `player_prose:
  Vec<String>` (the first text and each answer), `rounds:
  Vec<InferenceOutput>`, `calls: Vec<CallRecord>` (per tool call: its call id,
  the exact `CommandBody` or play patch persisted before submission, and its
  result string once known), `persona_turns: Vec<(SubjectId, PersonaTurn)>`,
  `question: Option<String>`, `refusal: Option<String>` (Q13), `narration:
  Option<String>`, `state: Running | AwaitingPlayer | Closed`.
  - The agent's conversation is re-derived from `opening_prompt`, `rounds` and
    the recorded results, the connector posture; nothing crosses from one turn
    to the next except world state. When a turn closes, the next turn's
    `opening_prompt` depends only on the snapshot and the new text, which is
    invariant 1's test.
  - Commands inside a turn carry ids derived from `(turn_id, round,
    call_index)` (sha256 → UUID, `CommandId::parse_uuid`); a call whose body is
    recorded and whose result is not is resubmitted with the recorded body.
  - After a restart, a `Running` turn resumes on the player's next `world.play`
    (the player's evidence rides that request; an empty text means
    "continue"), and an `AwaitingPlayer` turn waits for the answer. Nothing
    runs a player act without a live principal.
- **Depends on it:** Cut 8.
- **Ruling:** default as above.
- **Authority:** defaulted.

### PA-Q9 The Eve play surface

- **Asked:** 2026-09-22 (target Q9), narrowed by Q11's ruling.
- **Default design:** in Active, for the principal whose subject is
  `human_controller`, the surface is: the latest `narration` (the Projector's
  prose for the player; Q11) as a `text` card; the agent's `question` when one

  The story card (`eve.rs:436-455`) is deleted from the play surface: it is the

- **Depends on it:** Cut 9.
- **Ruling:** default as above.
- **Authority:** defaulted.

### PA-Q10 The player's subject

- **Asked:** 2026-09-22 (target Q10).
- **Finding:** the genesis human subject serves as the player's body, but not

### PA-Q12 Where the agent's read and write vocabulary lives

- **Asked:** 2026-09-22, from probe B. The target says the library gains three
  pieces and Dungeon owns the agent's loop, prompt and catalog. The Body says
  Dungeon cannot build or read an inference, cannot see positions, roles,
  resources, routes or knowledge, and cannot decode a patch tool call, because
  every one of those is `pub(crate)`.

  `crates/ghostlight/src/table.rs`. It holds the vocabulary any unconfined
  author running actors needs, and nothing about turns:

    with bracketed ids. It grows from `render_world_structure`, which moves
    here and which the seed lane then calls here. It must print every id an
    authoring tool takes, which today's renderer does not: resources are
    printed by label only (`elaboration.rs:2257-2263`) and facts not at all.

    id, its standing (`canonical | claimed by X | ruled`) and who knows it.

    TableError>`: a named subset of `PATCH_TOOLS`, refusing unknown names.

  - `pub fn describe_refusal(&WorldSnapshot, &KernelError) -> String`.
  - Two inference seams: `pub fn InferenceRequest::play(..)`, which wraps
    `tool_request` under a new `InferencePurpose::Play`, and `pub fn
    InferenceOutput::events(&self)`/`receipt_digest(&self)`.

  specifies it.

### PA-Q15 What the play authority may assert and mint

- **Asked:** 2026-09-22, from PA.f7: the play authority could state no fact
  of its own (a fact is `Canonical` with an evidence receipt, or `Claimed`
  by a subject) and could mint no quantity (`Admit` requires evidence), so
  the residue rule (anything untyped becomes a fact) had no standing for the
  agent's rulings.
- **Ruling:** the play authority's facts stand as `Ruled` by it, and the
  play authority mints quantity. The operator: "shackling the Ghostlight
  Dungeon agent to Njordr's invariants is crazy, if the agent can invent
  people, it can invent loot." Only `Play` gains either. Elaborators,
  consumers and the seed keep the evidence gate, so a consumer feeding
  Njordr keeps quantity provenance.
- **Authority:** operator.
- **Ruled:** 2026-09-22.
- **Supersedes:** PA-Q5's `PlayCarriesEvidence` refusal ("so it cannot
  mint quantity") and PA.f7. Cut 3 is respecified to match.
- **Depends on it:** Cut 3.
- **Body facts the design rests on** (read at `5ff1d54`):
  - The evidence gate is structural in the types, not a caller check.
    `FactStanding` is `Canonical { evidence }` or `Claimed { by }`
    (`patch.rs:298-303`), with `FactStandingRef` as its proposal twin
    (`:308-311`). `ComponentOp::Admit` and `ResolvedOp::Admit` carry a
    required `evidence: EvidenceRef` (`patch.rs:1055-1060`, `:1721-1726`).
    The resolver refuses a canonical fact or an `Admit` whose receipt is not in
    the same patch's `evidence` list (`FactWithoutEvidence`, `:3046-3052`;
    `AdmitWithoutEvidence`, `:3938-3944`). Apply re-checks both
    (`lib.rs:2044-2060`, `:2373-2390`), and so does replay's shape check
    (`journal.rs:580-590`).
  - The resolver is actor-blind. `resolve_patch(state, command_id, patch,
    scale_intent, lens_weights)` (`patch.rs:2947-2953`) is never told the
    caller. Every per-author rule runs after it, in `reduce`, and is
    re-decided in `apply_effect`: `require_patch_author` and
    `confine_to_ground` (`lib.rs:1655-1685`, `:4786-4802`).
  - The quantity ledger has one owner: `check_ledger` (`patch.rs:1877-1891`)
    credits `admitted`, and `apply_operations` recomputes the deltas
    (`lib.rs:2124-2150`).
  - `FactCandidate` (`patch.rs:2111`) is the resolver's view of a fact's
    standing. Its only standing-dependent rule is "evidenced knowledge is
    knowledge of canon" (`:4288-4296`), which apply repeats
    (`lib.rs:2638-2646`).
  - Subjects never see standing in prose. The snapshot lowers standing to
    `FactStandingView { Canonical, Claimed { by } }` (`lib.rs:1056-1059`,
    written at `:3660-3663`). The Projector's stimulus renders `how`
    (`said | seen_doing | known`, from `KnowledgeSource`), certainty and text,
    never standing (`controllers.rs:4616-4638`). Only the typed views
    (Interpreter, operational) print it (`controllers.rs:4675-4695`).
- **Design (for Cut 3):** two additive variants plus one author rule. `Admit`
  is not reshaped.
  - **Facts:** `FactStanding::Ruled` and `FactStandingRef::Ruled`, both unit
    variants. There is exactly one play authority and the journal's commit
    records its caller, so a field naming the ruler would be a second copy of
    the caller that could disagree with it. Lowering maps
    `FactStandingRef::Ruled → FactStanding::Ruled` (`patch.rs:4965-4972`), and
    `FactCandidate` gains `Ruled` (`:2111`, `:3184`, `:3340`). Canonical stays
    the only standing that evidenced knowledge may name, so a `Ruled` fact can
    be known `Witnessed` but never `Evidenced`.
  - **Quantity:** a new `ComponentOp::Mint { holder, resource, qty }` and
    `ResolvedOp::Mint`. It resolves like `Admit` without the receipt clause:
    holder and resource must resolve and `qty` must be nonzero. It credits the
    ledger as `admitted` (the ledger has no "minted" term to add; the equation
    `before + admitted + gained - consumed - spent = after` is unchanged), and
    `operation_ground` treats it like `Admit` (`lib.rs:4604-4606`).
  - **One author rule:** `require_ruler(caller, &ResolvedPatch) -> Result<(),
    Vec<Mismatch>>` collects every `Ruled` fact and every `Mint` op and
    refuses them with `Mismatch::RuledWithoutAuthority { site }` unless
    `caller == System(Play)`. It is called in `reduce`'s `AdmitPatch` arm after
    `resolve_patch`, beside `confine_to_ground`, and re-decided in
    `apply_effect`'s `PatchAdmitted` arm as an `Invariant` error, like
    confinement.
  - **Why this shape keeps the gate for everyone else:** `Canonical` and
    `Admit` keep their required receipts in the type, so every other author's
    evidence gate is exactly as it is today: the same predicate, at the same
    three sites, still reached for every author including `Play`. What `Play`
    gains is two new spellings that only `require_ruler` can admit. Neither
    existing check becomes "evidence or else".
  - **Subjects:** the snapshot maps `FactStanding::Ruled` to
    `FactStandingView::Canonical` (`lib.rs:3660-3663`). A ruled fact is world
    truth inside the fiction. Which door admitted it is non-fictional
    provenance, just as a receipt is (`lib.rs:1036-1039`), so no subject-facing
    surface distinguishes it. The Projector needs no change: a subject told or
    shown a ruled fact renders it `known` with certainty.
- **Option not taken:** turning `Admit.evidence` into an enum or `Option`
  (`Evidence(EvidenceRef) | Ruled`). That changes the wire shape of a
  consumer's `Admit` (`consumer.rs:547-552`, `ghostlight.consumer_patch.v0`)
  and the `admit` tool schema. It also moves the evidence gate out of the type
  and into a caller check, so every author's gate would depend on one
  condition that stays right.
